## 1. 背景与目标

### 1.1 背景

nowen-reader 是一个自托管的漫画/小说管理与阅读平台（Go + Gin 后端、SQLite、React 19 前端、Flutter 移动端），内容来源完全依赖**本地文件**：用户手动把文件放进 `./comics/`、`./novels/` 目录或通过 Web UI 上传，系统自动扫描入库。

Z-Library 是全球最大的电子书在线库之一（声称 1000 万+ 图书），但获取流程割裂：用户需要在浏览器登录镜像站 → 手动搜索 → 手动下载 → 手动拷贝到 NAS 目录 → 等待扫描。镜像域名经常变化，进一步增加摩擦。

### 1.2 目标

在 nowen-reader 内**原生集成 Z-Library 通道**，实现：

1. **不离开平台搜书**：在 Web UI 内按书名/作者/关键词搜索 Z-Library，支持语言、格式、年份、排序筛选；
2. **一键入库**：搜索结果点击「入库」，后台自动完成 下载 → 落盘 → 扫描 → 元数据回填，最终在书库中直接打开阅读；
3. **过程可见可控**：下载任务中心展示进度/失败原因，支持重试与取消；每日下载配额可视化。

### 1.3 非目标（本期不做）

- 不做 Z-Library 内容的再分发：本项目只做个人账号的私人工具，不含任何内置账号、代理缓存池或公开共享；
- 不做在线直读 Z-Library（不落盘的流式阅读）——必须先入库成为本地文件，与 nowen-reader 阅读器解耦；
- 不做 Z-Library 站内书架双向同步（save/unsave）；
- 不做账号自动注册、验证码绕过。

## 3. Z-Library 接入方式调研

### 3.1 接入结论

Z-Library **无官方公开 API**。采用社区已逆向并长期验证的 **eapi（安卓 App API）** 方案，代表实现与文档：

- 端点文档：[baroxyton/zlibrary-eapi-documentation](https://github.com/baroxyton/zlibrary-eapi-documentation)
- 参考实现：[bipinkrish/Zlibrary-API](https://github.com/bipinkrish/Zlibrary-API)（Python，单文件）、[heartleo/zlib](https://github.com/heartleo/zlib)（Go，含 eapi 文档校对）

选型理由：Go 技术栈可直接移植 heartleo/zlib 的客户端逻辑；eapi 相较于网页版（`/rpc.php`）接口更稳定、反爬更弱、返回结构更规整。

### 3.2 认证模型

```
邮箱/密码 ──POST /eapi/user/login──▶ 返回用户对象（含 id + remix_userkey）
                                          │
                                          ▼
          后续所有请求携带 Header:  remix-userid: <id> / remix-userkey: <key>
          （或 Cookie: remix_userid / remix_userkey）
```

- **推荐只持久化 `remix_userid` / `remix_userkey`**（相当于会话令牌），密码仅在首次登录换取令牌时使用，用后不落盘；令牌长期有效，失效时提示用户重新登录；
- 同时支持用户直接粘贴浏览器 Cookie 中的 `remix_userid` / `remix_userkey`（免密码登录）。

### 3.3 核心端点清单

Base URL 为用户可用的镜像域名（见 §3.4）。POST 请求体为 `application/x-www-form-urlencoded`，数组参数形如 `languages[]=chinese&languages[]=english`。

| 用途 | 端点 | 关键参数 / 说明 |
| --- | --- | --- |
| 登录 | `POST /eapi/user/login` | `email`, `password` |
| 用户资料 | `GET /eapi/user/profile` | 含每日下载配额/已用量（字段以实际响应为准，适配层映射） |
| 搜索 | `POST /eapi/book/search` | `message`、`yearFrom`、`yearTo`、`languages[]`、`extensions[]`、`order`、`page`、`limit` |
| 书籍详情 | `GET /eapi/book/{id}/{hash}` | 含完整元数据与下载链接 `dl`（指向**个人专属下载域名**） |
| 可用格式 | `GET /eapi/book/{id}/{hash}/formats` | 多格式书籍的格式列表 |
| 相似书籍 | `GET /eapi/book/{id}/{hash}/similar` | 二期可用于「找同系列」 |
| 元信息 | `GET /eapi/info/extensions`、`/eapi/info/languages`、`/eapi/info/domains` | 驱动筛选下拉框；domains 可辅助域名发现 |

> 请求需带常规浏览器/客户端 `User-Agent`；`id`+`hash` 是书籍的复合主键，贯穿搜索→详情→下载全链路。

### 3.4 域名策略

| 类别 | 域名 | 用途 |
| --- | --- | --- |
| 主站 | `https://z-lib.sk` | 默认 |
| 镜像 | `z-lib.fm`、`zh.z-lib.gd`、`zlib.fi`、`zlib.by` | 备选，可增删 |
| 个人下载域名 | 登录后由平台分配（书详情 `dl` 字段返回） | 仅下载文件时使用 |

设计要点：

1. 域名列表**存于服务端配置**，用户可增删改、可指定默认域名；
2. 内置**健康检查**（探测 `/eapi/info` 或登录态 `/eapi/user/profile`），失败自动切换下一个可用域名；
3. 下载必须使用个人域名：从书籍详情响应中解析，缓存备用；
4. 设置页提供「全部域名不可达」时的兜底指引：向 `blackbox@z-library.so` 发送任意邮件，系统自动回复最新可用域名（人工操作 + 一键复制邮箱地址 + 手动填入）。

### 3.5 限制与风险（决定多处交互设计）

| 限制 | 影响 | 应对 |
| --- | --- | --- |
| 免费账号每日下载限额（约 10 本/日，以账号实际为准） | 入库是稀缺操作 | 配额常显 + 下载前预检 + 超限明确报错（任务标失败、次日可一键重试） |
| 免费账号单文件大小上限 | 大文件下载可能被拒 | 下载前对比文件大小与账号档位，前端提前灰置/提示 |
| 无官方 API，接口可能随时变动 | 客户端可能失效 | eapi 调用收敛到独立适配层（一个包），字段映射集中管理；响应结构未知字段宽容处理 |
| Cloudflare/反爬拦截 | 请求 403/挑战页 | 检测特征自动换镜像重试；仍失败则提示用户在浏览器完成一次验证或更新 Cookie |
| 搜索结果字段非契约化 | 解析失败 | 适配层做防御性解析 + 单元测试固定样本 |

## 5. 功能需求

> 优先级：P0 = MVP 必须，P1 = 二期，P2 = 三期/可选。
> FR-xx 编号用于后续任务拆解与测试用例追溯。

### FR-1 账号与连接管理（P0，仅管理员）

- **FR-1.1** 设置页新增「Z-Library」分区，支持两种凭据方式：
  - a) 邮箱 + 密码（登录后立即换取并仅保存 `remix_userid`/`remix_userkey`，密码用后即弃，不落库不落日志）；
  - b) 直接粘贴 `remix_userid` + `remix_userkey`（从浏览器 Cookie 获取，UI 提供获取指引）。
- **FR-1.2** 「测试连接」按钮：调用 profile 端点，回显账号名、账号类型（免费/捐赠者）、每日配额与已用数。
- **FR-1.3** 凭据存储于服务端（SQLite 配置表），`remix_userkey` 使用 AES-GCM 加密存储，密钥来自部署时环境变量（`SL_ZLIB_SECRET`，未配置时自动生成并持久化到数据目录）。
- **FR-1.4** 令牌失效（401/登录态校验失败）时：状态置为「已断开」，任务中心与搜索页出现重连引导；管理员的设置页标红。
- **FR-1.5** 支持解绑（清除凭据），二次确认。

### FR-2 域名与故障转移（P0）

- **FR-2.1** 预置 §3.4 域名列表，管理员可增/删/改、拖拽排序（排序即优先级）、指定默认域名。
- **FR-2.2** 健康检查：手动按钮 + 自动（每次请求失败时标记该域名为「不健康」，冷却 N 分钟内不再首选）。
- **FR-2.3** 请求级故障转移：当前域名请求失败（网络错误/5xx/CF 拦截）时自动重试下一域名，单次用户操作最多遍历全部启用域名一轮。
- **FR-2.4** 个人下载域名：从书籍详情 `dl` 字段自动解析并缓存；下载始终走个人域名。
- **FR-2.5** 全部域名不可达时：UI 明确提示，并展示 blackbox 邮箱兜底指引（复制邮箱 + 手动填入新域名的入口）。
- **FR-2.6** 状态页展示：当前生效域名、各域名最近一次探测结果。

### FR-3 Z-Library 搜索（P0）

- **FR-3.1** 侧边栏/顶部导航新增「Z-Library」入口（仅对有权限用户可见，见 FR-10）。
- **FR-3.2** 搜索框 + 筛选器：
  - 语言（多选，选项来自 `/eapi/info/languages` 缓存，默认不限）；
  - 格式（多选：EPUB/MOBI/AZW3/PDF/TXT/HTML/CBZ/CBR/ZIP/RAR…，来自 `/eapi/info/extensions`）；
  - 年份区间（可选）；
  - 排序：最佳匹配 / 最新 / 最受欢迎（`order` 参数）。
- **FR-3.3** 结果列表（卡片/表格双视图可选，跟随现有 UI 风格）每项展示：封面、书名、副标题、作者、出版社、年份、语言、格式、文件大小、评分；**每项状态标注**：未入库 / 已入库（含指向本地条目的链接）/ 队列中。
- **FR-3.4** 分页加载（`page`/`limit`，默认 limit=20），支持加载更多。
- **FR-3.5** 搜索历史（本地 localStorage，最近 10 条，可清空）。
- **FR-3.6** 点击结果卡片展开**详情面板**：完整描述、封面大图、格式列表（`/formats`）、相似推荐（P1）、「入库」按钮 + 目标书库选择。
- **FR-3.7** 搜索请求超时 15s，失败给出可读原因（域名不可达 / 需重新登录 / 被风控）。

### FR-4 一键入库（P0，核心）

**入库流水线**（后端任务，状态机见 FR-5）：

```
[用户点击入库]
  1. 前置校验（同步、<1s）
     a. 登录态有效？ → 否：提示重连
     b. 今日剩余配额 > 0？ → 否：直接失败，说明恢复时间
     c. 目标书库类型允许该扩展名？ → 否：警告并阻止（可强制）
     d. 去重检查（id+hash 已入库或已在队列）→ 是：提示并指向已有条目
  2. 创建下载任务（queued），立即返回任务 ID，UI 进入任务中心视角
  3. 队列调度（并发上限默认 1，可配 1~3）
     a. GET /eapi/book/{id}/{hash} 获取最新详情与 dl 链接
     b. 若多格式书籍且未指定格式 → 按优先级 epub > pdf > mobi > azw3 > 其他 自动选择
     c. 流式下载到 临时文件（记录进度：已下载字节/总字节）
     d. 完整性校验：扩展名 + 魔数（EPUB/CBZ=PK，PDF=%PDF…），失败重试 1 次
  4. 落盘
     a. 目标目录 = 目标书库根目录
     b. 文件名 = 「书名 - 作者.ext」（清洗非法字符、长度截断、重名加 (2) 后缀）
     c. move 临时文件 → 正式文件
  5. 触发该目标书库扫描（POST /api/libraries/:id/scan），从扫描结果中匹配新增条目
  6. 元数据回填（见 FR-8）
  7. 任务置 completed，记录 zbook(id+hash) ↔ 本地 book 映射
  8. UI 通知：「《书名》已入库」→ 点击跳转书籍详情
```

- **FR-4.1** 目标书库选择：默认值 = 与扩展名匹配类型的第一个可用书库（novel→默认小说库，comic→默认漫画库）；用户入库时可临时切换到任何自己 canManage 的书库；选择被记忆为下次默认。
- **FR-4.2** 格式选择：多格式书籍在详情面板提供格式单选；列表卡片快速入库用默认优先级。
- **FR-4.3** 失败语义：任何一步失败，任务置 failed 并记录**具体阶段与原因**；不产生半截文件（临时文件清理）；配额已消耗的失败（如下载中断在限额内）如实标注。
- **FR-4.4** 幂等与重试：failed 任务可重试，重试前重新做前置校验；completed 任务不重复下载（除非用户明确「重新下载」）。
- **FR-4.5** 磁盘防护：落盘前检查目标卷剩余空间 > 文件大小 × 1.1，不足则失败并提示。
- **FR-4.6** 全程通过标准入库路径（磁盘文件 + 扫描），**不绕过** nowen-reader 的扫描器，保证后续删除、重扫、去重等行为一致。

### FR-5 下载任务中心（P0）

- **FR-5.1** 数据模型 `zlibrary_download_tasks`：

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| user_id | 发起人 |
| zbook_id / zbook_hash | Z-Library 书籍复合标识 |
| title / author / ext / filesize | 冗余快照（列表展示用） |
| library_id | 目标书库 |
| local_book_id | 入库成功后的本地书籍 ID |
| status | queued / downloading / completed / failed / canceled |
| progress | 0-100（下载中实时更新） |
| stage | 当前阶段：fetch_info / downloading / validating / moving / scanning / metadata |
| error_code / error_msg | 失败原因（结构化，见 §7 错误矩阵） |
| retry_count | 重试次数 |
| created_at / finished_at | 时间戳 |

- **FR-5.2** UI：全局入口（侧边栏图标 + 活动任务数角标），抽屉/页面展示任务列表；下载中任务显示进度条与阶段文案；支持取消（下载中=中断+清理临时文件；排队中=直接移除）。
- **FR-5.3** 推送：任务状态变化通过轮询（P0，2s 间隔）更新；P1 可升级 SSE/WebSocket（跟随 nowen-reader 现有推送能力）。
- **FR-5.4** 历史记录保留最近 200 条，可手动清空。

### FR-6 配额管理（P0）

- **FR-6.1** 配额数据来源：`/eapi/user/profile` 响应字段映射（适配层负责，兼容免费/捐赠账号不同字段）。
- **FR-6.2** 展示位置：Z-Library 搜索页顶部（`今日剩余 x/y`）+ 设置页连接状态。
- **FR-6.3** 每次下载完成后主动刷新配额；下载前用本地计数预检（避免超限请求浪费）。
- **FR-6.4** 配额审计：任务中心可按日期筛选，管理员可见**全部用户**的任务；普通用户仅见自己的。

### FR-7 去重（P0）

- **FR-7.1** 数据模型 `zlibrary_imported_books`：`zbook_id`、`zbook_hash`、`local_book_id`、`library_id`、`imported_at`、`imported_by`，唯一索引 `(zbook_id, zbook_hash)`。
- **FR-7.2** 去重粒度 = id+hash（同一 book 的不同格式算不同 hash，允许分别入库，但同格式重复拦截）。
- **FR-7.3** 搜索结果渲染时批量查询去重状态，标注「已入库」。
- **FR-7.4** 本地条目被删除后：映射保留但标记 `local_book_id` 失效，此时允许再次入库。

### FR-8 元数据回填（P1）

- **FR-8.1** 入库时将 Z-Library 元数据（书名/副标题/作者/出版社/年份/语言/描述/封面 URL）随任务保存。
- **FR-8.2** 扫描匹配到本地条目后，通过现有 `POST /api/metadata/apply` 写入；封面下载到本地后上传为该条目封面。
- **FR-8.3** 文件名规范「书名 - 作者.ext」保证即使元数据回填失败，现有 AI/规则解析也能得到基础元数据。
- **FR-8.4** 回填失败不阻断入库（降级为仅文件名入库），任务仍标 completed，元数据缺失用 warning 标注。

### FR-9 设置界面汇总（P0）

「设置 → Z-Library」（管理员）分区包含：

1. 连接：凭据方式、测试连接、解绑；
2. 域名：列表管理、健康检查、默认域名、个人域名显示；
3. 下载行为：并发数（1~3）、目标书库默认值、格式优先级、自动元数据回填开关；
4. 权限：启用 Z-Library 功能的用户范围（见 FR-10）；
5. 兜底指引：blackbox 邮箱说明。

### FR-10 权限控制（P0）

- **FR-10.1** Z-Library **配置与凭据**仅管理员可见可用。
- **FR-10.2** 搜索与入库权限：新增设置项「允许使用 Z-Library 的用户范围」，三档：
  - a) 仅管理员（默认）；
  - b) 拥有任意书库 canManage 的用户；
  - c) 所有登录用户（入库仍要求目标书库 canManage，与上传权限模型一致）。
- **FR-10.3** 所有新端点复用现有鉴权中间件与权限矩阵，未授权返回 403。

### FR-11 移动端 Flutter（P2）

- App 内新增 Z-Library 搜索页与任务列表，复用后端全部端点；
- 入库后通过现有书库刷新机制展示；
- 与 Web 端共享配额与去重。

### FR-12 愿望单/自动追更（P2，可选）

- 收藏 Z-Library 书籍到愿望单（本地表，不写 Z-Library 书架）；
- 每日定时检查：配额有剩余时按愿望单优先级自动入库；
- 需求待用户确认后再细化，本期仅占位。

## 6. 技术方案概要

### 6.1 后端模块划分（Go）

```
internal/zlibrary/            # 新增独立适配包（与业务解耦，便于上游变更时单点维护）
├── client.go                 # HTTP 客户端：域名轮换、UA、超时、重试、CF 拦截识别
├── auth.go                   # login / token 校验 / profile
├── search.go                 # search 请求构造 + 响应防御性解析 → 统一 ZBook 结构
├── book.go                   # 详情 / formats / 下载链接解析（个人域名）
├── download.go               # 流式下载 + 进度回调 + 校验
├── models.go                 # ZBook / ZProfile / 统一错误类型
└── client_test.go            # 用固定样本响应做解析单测

internal/zlibrary/service/    # 业务层：任务队列、状态机、去重、配额缓存、元数据回填
internal/server/api/zlibrary* # Gin 路由 + 请求校验 + 权限检查
```

### 6.2 新增 REST API（草案）

统一前缀 `/api/zlibrary`，复用 Bearer/Cookie 认证：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/status` | 配置者 | 连接状态、配额、当前域名、各域名健康 |
| PUT | `/settings` | 管理员 | 保存凭据/域名/行为配置 |
| POST | `/auth/test` | 管理员 | 测试连接 |
| DELETE | `/auth` | 管理员 | 解绑 |
| POST | `/search` | 配置者 | `{message, languages[], extensions[], yearFrom, yearTo, order, page, limit}` → 统一结果结构（含去重标注） |
| GET | `/book/:id/:hash` | 配置者 | 详情（含格式列表、已入库标注） |
| POST | `/downloads` | 配置者 | `{zbookId, hash, ext?, libraryId?}` 创建任务 |
| GET | `/downloads` | 配置者 | 任务列表（管理员可查全部） |
| POST | `/downloads/:id/retry` | 发起人/管理员 | 重试 |
| DELETE | `/downloads/:id` | 发起人/管理员 | 取消/删除记录 |
| POST | `/domains/health-check` | 管理员 | 手动探测 |

### 6.3 前端页面（React）

| 位置 | 内容 |
| --- | --- |
| 新路由 `/zlibrary` | 搜索页：筛选栏 + 结果列表/网格 + 详情抽屉 + 入库按钮 + 配额条 |
| 全局任务中心 | 侧边栏图标 + 抽屉（进度/阶段/重试/取消） |
| 设置页新 Tab | §FR-9 五个分组 |
| 书库详情页 | 已入库条目显示来源「Z-Library」徽标（P1） |

### 6.4 与上游的合并策略

为降低后续跟随上游更新的成本：

1. 新功能尽量以**新增文件/新增包**实现，避免侵入修改原有文件；
2. 必须修改的原文件（路由注册、侧边栏导航、设置页、i18n 词条、migrations）集中在少量入口点，并在代码注释标注 `// s-library:` 便于 rebase 定位；
3. 记录 fork 基线 commit，跟随上游发版时按该清单核对冲突。

## 7. 错误处理矩阵

| 错误码（内部） | 场景 | 用户可见文案（zh） | 自动处理 |
| --- | --- | --- | --- |
| `Z_AUTH_REQUIRED` | 未配置凭据/令牌失效 | 「Z-Library 未连接，请在设置中登录」 | 状态置断开，任务不排队 |
| `Z_AUTH_FAILED` | 账号密码错误 | 「登录失败：邮箱或密码错误」 | 无 |
| `Z_QUOTA_EXCEEDED` | 今日额度用尽 | 「今日下载额度已用完（x/y），将于每日 xx 重置」 | 任务失败，可次日重试 |
| `Z_SIZE_LIMIT` | 超过账号单文件上限 | 「该文件超过当前账号的大小上限」 | 下载前预检拦截 |
| `Z_DOMAIN_UNREACHABLE` | 域名全部不可达 | 「所有 Z-Library 域名均无法访问，可尝试邮件获取新域名」 | 展示 blackbox 指引 |
| `Z_BLOCKED` | CF 挑战/风控 | 「访问被拦截，请在浏览器打开 xx 完成验证，或稍后重试」 | 换域名重试一轮 |
| `Z_NOT_FOUND` | 书籍下架/链接失效 | 「该书在 Z-Library 已不可用」 | 任务失败 |
| `Z_EXT_MISMATCH` | 目标书库类型不允许该格式 | 「epub 无法加入漫画书库」 | 前端预检，后端兜底 |
| `Z_DISK_FULL` | 磁盘空间不足 | 「目标书库所在磁盘空间不足」 | 预检拦截 |
| `Z_DUP_IMPORTED` / `Z_DUP_QUEUED` | 重复入库 | 「已入库，点击查看」/「已在下载队列中」 | 前端预检 |
| `Z_SCAN_FAILED` | 扫描未匹配到新条目 | 「文件已下载但入库失败，请手动扫描或查看日志」 | 文件保留，任务标 warning |
| `Z_META_FAILED` | 元数据回填失败 | 无弹窗，任务详情 warning | 降级完成 |

## 8. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 搜索 P95 < 5s（依赖上游站点，超时 15s）；任务状态轮询 2s；对 Z-Library 请求全局限速（默认串行下载），避免触发风控 |
| 安全 | `remix_userkey` 加密落库；密码不落库/不落日志；所有 Z-Library 流量仅由**服务端**发起（浏览器不直连，规避 CORS 与 IP 暴露）；日志脱敏 |
| 稳定性 | 适配层防御性解析，未知字段不报错；上游结构变更时仅改适配层 |
| i18n | 新增 UI 文案 zh/en 双语 |
| 兼容 | 不改变现有书库/阅读/用户行为；Docker 镜像体积增量 < 5MB |
| 合规 | 项目页显著位置声明：仅供个人学习研究，用户需自行遵守当地法律与 Z-Library 服务条款；本仓库不分发任何书籍内容 |
| 许可证 | 保持 GPL-3.0，保留原版权声明，修改文件头注明变更 |

## 10. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| eapi 接口变更导致功能失效 | 高 | 适配层隔离 + 固定样本单测 + 关注上游社区（baroxyton 文档/heartleo/zlib）快速跟进 |
| 账号被风控/封禁（高频请求） | 中 | 串行下载 + 请求间隔 + 失败退避；文档提示合理使用 |
| 免费额度太少影响体验 | 中 | 配额可视化 + 愿望单按优先级消耗（M3）；不做自动注册等灰色手段 |
| 上游 nowen-reader 大版本重构，rebase 成本高 | 中 | §6.4 隔离策略；必要时长期维护自己的分支 |
| 法律与合规 | 中 | 明确个人工具定位、免责声明、不分发内容 |
