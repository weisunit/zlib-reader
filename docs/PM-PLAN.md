# s-library M1 产品计划（PM-PLAN）

> 依据需求基线 `docs/REQUIREMENTS.md`（v0.1）做出的产品决策与 M1 执行计划。
> 文档版本 v1.0 · 日期 2026-11-09 · 维护角色：PM
> 下游输入：架构师（§5.1）、UI/UX 设计师（§5.2）、开发工程师（§5.3）

## 1. 开放问题决策（对应需求文档 §11，原则：默认保守、可后调）

### D1 权限默认档 → 默认「仅管理员」（FR-10.2 a 档）

Z-Library 下载配额是稀缺资源（免费账号约 10 本/日），且入库行为直接关联账号风控，默认放开到全用户会让管理员失去对配额消耗的控制。三档能力照需求实现，仅默认值取最保守档；管理员可随时在设置页放宽到 b/c 档，无需改代码。

### D2 元数据回填 → 不进 M1，放 M2

M1 只做两件低成本的事：FR-8.1（Z-Library 元数据随任务落库保存）+ FR-8.3（落盘文件名规范「书名 - 作者.ext」）。文件名规范已能保证扫描后基础可识别，现有 AI/规则解析可兜底；而完整回填（`metadata/apply` 对接 + 封面下载上传）约占 MVP 工期 20%，收益是锦上添花。因为 FR-8.1 数据已保存，M2 做回填时无需重新下载。

### D3 多账号轮换 → 不做，维持 M3

多账号会带来凭据管理复杂度翻倍、轮换策略、审计归属等一串问题，而个人自用场景下「单账号 + 配额可视化」已经够用。先上线观察真实配额消耗速度，若确实不够再启动 M3 的捐赠账号池方案。

### D4 UI 品牌 → 代码名 s-library，UI 沿用「弄文阅读」

改品牌牵动 Logo、i18n、打包元数据、文档截图等一串改动，且对用户无实际价值，M1 不做。Z-Library 来源的内容通过「Z-Library」小徽标区分（搜索页入口、任务中心、详情面板），避免用户误以为是平台内置资源。后续若需独立品牌再统一调整。

### D5 部署 → 保持上游 docker-compose 直接可用

自托管用户的迁移成本必须趋近于零：不新增端口、不新增必需配置。`docker-compose.prod.yml` 结构不变，仅新增可选环境变量 `SL_ZLIB_SECRET`（未配置时自动生成并持久化到数据目录，见 FR-1.3），拉新镜像即用。

## 2. M1 用户故事（16 条）

> 角色说明：「管理员」= admin；「授权用户」= 通过 FR-10.2 档位检查、可使用 Z-Library 搜索/入库的用户。
> 编号规则：B=后端先行，F=前端跟进，E=联调收尾；每条标注对应 FR 编号与优先级（M1 全部 P0）。

### A 组 · 后端先行（地基与流水线）

**US-M1-01 Z-Library 账号连接与凭据管理**（FR-1.1 / 1.2 / 1.3 / 1.5 · 管理员 · P0）
作为管理员，我要在服务端配置 Z-Library 凭据并验证连接，使平台能以我的账号访问 Z-Library。
- Given 未配置凭据，When 提交邮箱+密码并点「测试连接」，Then 服务端登录换取 `remix_userid`/`remix_userkey`，密码用后即弃（不落库、不落日志），回显账号名/账号类型/每日配额。
- Given 凭据已保存，When 再次查看设置，Then 凭据不以明文回显（userkey AES-GCM 加密落库），且支持直接粘贴 remix 令牌免密登录。
- Given 令牌失效（401），When 任意授权用户触发搜索/下载，Then 全局状态置「已断开」，设置页标红并出现重连引导；解绑操作需二次确认。

**US-M1-02 域名管理与请求级故障转移**（FR-2.1 / 2.3 / 2.4 / 2.5 · 管理员 · P0）
作为管理员，我要维护镜像域名列表并在域名故障时自动切换，保证请求成功率。
- Given 域名列表页，When 增/删/改/排序/指定默认域名并保存，Then 列表持久化且顺序即优先级。
- Given 当前域名请求失败（网络错误/5xx/CF 拦截），When 发起任意请求，Then 自动重试下一域名，单次用户操作最多遍历启用域名一轮；被标记不健康的域名冷却期内不再首选。
- Given 书籍详情返回个人下载域名 `dl`，When 下载文件，Then 始终使用个人域名并缓存备用。
- Given 全部域名不可达，When 用户发起搜索/下载，Then 返回 `Z_DOMAIN_UNREACHABLE`，UI 展示 blackbox 邮箱兜底指引（复制邮箱 + 手动填入入口）。

**US-M1-03 eapi 搜索与详情接口**（FR-3.2 / 3.4 / 3.6 / 3.7 / FR-7.3 后端部分 · 授权用户 · P0）
作为授权用户，我要通过后端代理搜索 Z-Library 并获取书籍详情，无需浏览器直连。
- Given 合法搜索请求，When POST `/api/zlibrary/search`，Then 按 `message/languages[]/extensions[]/yearFrom/yearTo/order/page/limit` 代理 eapi，返回统一结构（封面/书名/作者/年份/语言/格式/大小/评分），未知字段不报错。
- Given 搜索响应返回，Then 每项附带去重状态标注（未入库/已入库/队列中）。
- Given 请求书籍详情，When GET `/api/zlibrary/book/:id/:hash`，Then 返回完整描述与格式列表（`/formats`）。
- Given 上游超时或失败，When 超过 15s 或请求失败，Then 返回可读错误（域名不可达/需重新登录/被风控三分类）。

**US-M1-04 入库前置校验**（FR-4.1 前置校验 / FR-6.3 / FR-7.1 / 7.2 · 授权用户 · P0）
作为系统，我要在创建下载任务前完成同步预检，避免浪费配额与产生无效任务。
- Given 用户提交入库请求，When 后端校验，Then 依次检查：登录态有效 → 今日剩余配额 > 0（本地计数预检）→ 目标书库类型允许该扩展名 → id+hash 未入库且未在队列，任一不通过则同步返回对应错误码（<1s），不创建任务。
- Given 校验通过，When 创建任务，Then 任务落库 `zlibrary_download_tasks`（含用户、zbook id+hash、快照字段、目标书库），立即返回任务 ID。
- Given `zlibrary_imported_books` 表，When 同一 id+hash 重复请求，Then 唯一索引兜底拦截，返回 `Z_DUP_IMPORTED`/`Z_DUP_QUEUED` 并附已有本地条目 ID。

**US-M1-05 下载任务流水线与状态机**（FR-4.2 / 4.3 / 4.4 / 4.5 / 4.6 / FR-5.1 · 系统 · P0）
作为系统，我要按「取详情 → 下载 → 校验 → 落盘 → 触发扫描」执行任务，保证磁盘是唯一事实来源。
- Given 任务进入调度，When 并发槽空闲（默认 1，可配 1~3），Then 拉取书籍详情解析 `dl` 链接；多格式未指定时按 epub > pdf > mobi > azw3 > 其他自动选择。
- Given 开始下载，Then 流式写临时文件并实时更新 progress/stage；完成后做扩展名+魔数校验（EPUB/CBZ=PK、PDF=%PDF），失败重试 1 次。
- Given 校验通过，Then 落盘前检查目标卷剩余空间 > 文件 × 1.1；文件名「书名 - 作者.ext」（清洗非法字符、长度截断、重名加 (2)）；move 到目标书库根目录。
- Given 落盘成功，When 触发该目标书库扫描（复用现有 scan 路径，不绕过扫描器），Then 从扫描结果匹配新增条目并写入 `zlibrary_imported_books` 映射，任务置 completed。
- Given 任意一步失败，Then 任务置 failed 并记录阶段与结构化错误码，临时文件清理，不产生半截文件。

**US-M1-06 任务中心 API**（FR-5.1 / 5.4 / FR-6.4 基础部分 · 授权用户 · P0）
作为授权用户，我要查询/重试/取消下载任务，掌握入库过程。
- Given 任务列表请求，When GET `/api/zlibrary/downloads`，Then 普通用户仅见自己的任务，管理员可见全部用户的任务。
- Given failed 任务，When POST `/downloads/:id/retry`，Then 重新执行前置校验后重新排队，retry_count 递增；completed 任务不提供重试。
- Given queued/downloading 任务，When DELETE `/downloads/:id`，Then 排队中直接移除；下载中中断并清理临时文件，状态置 canceled。
- Given 历史超过 200 条，When 新任务完成，Then 保留最近 200 条，支持手动清空。

**US-M1-07 配额数据源与刷新**（FR-6.1 / 6.3 · 授权用户 · P0）
作为系统，我要维护准确的每日配额数据，支撑预检与展示。
- Given 账号已连接，When 调用 profile 端点，Then 适配层映射免费/捐赠账号的不同字段为统一「今日已用/总量」结构。
- Given 每次下载完成（成功或消耗配额的失败），Then 主动刷新配额缓存；搜索页与设置页读取缓存值。

**US-M1-08 Z-Library 权限档与端点鉴权**（FR-10.1 / 10.2 / 10.3 · 管理员 · P0）
作为管理员，我要控制谁可以使用 Z-Library 功能，且所有新端点受统一鉴权保护。
- Given 设置项「允许使用 Z-Library 的用户范围」，When 管理员选择三档之一，Then 生效：a 仅管理员 / b 任意书库 canManage 用户 / c 所有登录用户（入库仍要求目标书库 canManage）。
- Given 未授权用户请求任一 `/api/zlibrary/*` 端点，Then 返回 403；配置类端点（凭据/域名/设置）始终仅管理员。
- Given 用户未登录或 Key 无效，Then 复用现有认证中间件返回 401。

### B 组 · 前端跟进（页面与交互）

**US-M1-09 设置页「Z-Library」分区**（FR-1 / FR-2.6 / FR-9 · 管理员 · P0）
作为管理员，我要在一个分区里完成连接、域名、下载行为、权限配置。
- Given 设置页，When 进入 Z-Library 分区，Then 包含：连接（凭据/测试/解绑/状态）、域名列表管理（排序即优先级、各域名最近探测结果）、下载行为（并发数 1~3、默认目标书库）、权限三档、blackbox 兜底指引。
- Given 操作成功或失败，Then 有明确反馈；密码框不回显；文案 zh/en 双语。

**US-M1-10 搜索页与筛选**（FR-3.1 / 3.2 / 3.3 / 3.4 / 3.5 · 授权用户 · P0）
作为授权用户，我要在平台内搜索 Z-Library 并筛选结果。
- Given 导航新增「Z-Library」入口，When 仅授权用户可见并进入 `/zlibrary`，Then 页面顶部常显「今日剩余 x/y」配额。
- Given 输入关键词，When 应用语言/格式/年份/排序筛选并搜索，Then 5s 内呈现带封面的结果列表，结果项标注「未入库/已入库（可跳转本地条目）/队列中」。
- Given 结果较多，When 加载更多，Then 按页追加（默认 limit=20）；搜索历史存 localStorage 最近 10 条，可清空。

**US-M1-11 书籍详情面板与一键入库**（FR-3.6 / FR-4.1 / 4.2 · 授权用户 · P0）
作为授权用户，我点一下「入库」就能等书出现在书库里，全程无需其他操作。
- Given 点击结果卡片，When 展开详情面板，Then 显示完整描述、封面大图、格式列表、「入库」按钮与目标书库选择。
- Given 多格式书籍，When 用户在详情面板选择格式，Then 单选生效；从列表卡片快速入库时使用默认格式优先级，不打断主流程。
- Given 点击入库，When 前置校验失败，Then 按错误码给出可读提示与下一步动作（重连/次日重试/换书库/查看已有条目）；校验通过则提示「已加入任务队列」并引导至任务中心，目标书库选择被记忆为下次默认。

**US-M1-12 任务中心 UI**（FR-5.2 / 5.3 · 授权用户 · P0）
作为授权用户，我要实时看到下载进度并管理任务。
- Given 侧边栏任务图标，When 有活动任务，Then 显示数量角标；点开抽屉展示任务列表（含他人任务对管理员可见标识）。
- Given 任务下载中，When 轮询刷新（2s），Then 进度条与阶段文案（取详情/下载中/校验/落盘/扫描中）实时更新。
- Given 任务失败/排队中/已完成，When 操作，Then 分别可重试/取消/跳转本地条目；失败原因展示人话文案。

**US-M1-13 配额展示**（FR-6.2 · 授权用户 · P0）
作为授权用户，我要随时知道今天还剩几次下载。
- Given 搜索页顶部，When 页面加载或下载完成后，Then 配额条更新为最新「今日剩余 x/y」。
- Given 配额为 0，When 用户点击入库，Then 立即提示恢复时间（`Z_QUOTA_EXCEEDED`），不创建任务。

### C 组 · 联调收尾（真实账号验收）

**US-M1-14 全链路验收：搜 → 入 → 读**（对应需求 US-1/2/4 · 管理员 · P0）
- Given 真实账号与真实书库，When 管理员配置连接后搜索一本书并点击入库，Then 无需离开平台，文件自动落盘、扫描入库、任务置 completed，从通知点击直达书籍详情并可正常阅读。
- Given 换 epub/mobi/PDF 三类格式与漫画/小说两类书库，Then 扩展名路由与类型校验均正确。

**US-M1-15 错误路径与文案落地**（§7 错误矩阵全量 · 授权用户 · P0）
- Given §7 错误矩阵中每一条 M1 触发场景（断连/密码错/超限/全域名不可达/被拦截/下架/扩展名不符/磁盘满/重复/扫描失败），When 各场景被触发，Then 用户看到矩阵中的中文文案（含 en 翻译）与对应自动处理行为，无裸错误码、无英文堆栈。

**US-M1-16 去重与重试专项验证**（对应需求 US-6 / FR-4.4 / FR-7.4 · 授权用户 · P0）
- Given 同一本书（同 id+hash），When 重复点击入库/重试，Then 提示已入库或已在队列，配额不重复消耗。
- Given 已入库条目在书库中被删除，When 再次搜索该书，Then 显示「未入库」且允许再次入库（映射标记 local_book_id 失效）。

| 多账号轮换 | M3 | 决策 D3 |

### 3.3 边界情况决策

1. **下载中断但配额已消耗**：如实标注，不做补偿——任务置 failed，错误信息注明「已消耗今日配额，次日恢复后可重试」。若中断后临时文件实际完整（魔数校验通过），则照常完成入库，不算失败。绝不自动重复下载同一本书来「找回」配额。
2. **扫描匹配不到新条目（Z_SCAN_FAILED）**：文件保留在目标书库根目录（磁盘是事实来源，不删除、不移动），任务置 failed 并附「手动扫描」入口与日志指引；仅自动补触发 1 次扫描，不无限重试。M1 靠文件名规范（书名 - 作者）最大化匹配率，M2 元数据回填进一步降低此概率。
3. **目标书库被删除**：创建任务时与落盘前各校验一次书库存在性；已删除则任务失败，提示重新选择书库重试（重试不重复消耗配额，因未发起下载）。若文件已落盘后书库才被删，文件保留原地，用户可手动扫描或移入其他书库。
4. **Z-Library 端书籍下架/链接失效（Z_NOT_FOUND）**：任务失败并明确告知「该书在 Z-Library 已不可用」；未发起下载则不消耗配额。
5. **重复点击入库**：前端预检提示 + 后端 `(zbook_id, zbook_hash)` 唯一索引兜底，双保险；提示文案区分「已入库（可查看）」与「已在队列中」。
6. **磁盘空间不足**：下载前预检（剩余空间 > 文件 × 1.1），直接拦截、不发起下载、不耗配额，提示清理或更换书库。

## 4. 给下游角色的约束提示

### 4.1 给架构师

- **磁盘文件 + 扫描是唯一入库路径**（FR-4.6）：下载落盘后只允许通过现有扫描机制入库，禁止直写 books 表或绕过扫描器，保证删除、重扫、去重行为与手动放置文件完全一致。
- eapi 调用收敛到 `internal/zlibrary` 单一适配包，业务层不得直接拼 Z-Library 请求；上游接口变更时只改适配层。
- 所有 Z-Library 流量仅由服务端发起，浏览器不直连 Z-Library（规避 CORS 与用户 IP 暴露）。
- 新端点统一挂 `/api/zlibrary` 前缀，复用现有会话/Bearer 认证中间件与权限矩阵，不另起鉴权体系。
- 遵循需求 §6.4 合并策略：新功能以新增文件/包为主，必须修改的原文件（路由注册、侧边栏、设置页、i18n、migrations）集中在少量入口点并标注 `// s-library:`；记录 fork 基线 commit。
- SQLite 新表（`zlibrary_download_tasks`、`zlibrary_imported_books`、配置表）走现有 migrations 模式；任务状态机字段见 FR-5.1，不额外发明字段。

### 4.2 给 UI/UX 设计师

- **入库必须一键完成**：列表卡片快速入库不得弹出任何打断性对话框；格式选择与书库切换只在详情面板提供，且都有合理默认值。
- 全程跟随 nowen-reader 现有设计语言、导航结构与 zh/en 双语要求；新增文案必须两条语言都提供。
- 每个错误状态必须同时给出「原因人话 + 下一步动作」（重连/重试/换书库/兜底指引），禁止裸错误码或技术堆栈直接暴露给用户。
- 配额在搜索页顶部常显；任务中心为全局入口（侧边栏 + 角标），不藏在设置里。
- 密码与 remix_userkey 输入框一律不回显；搜索结果对「已入库/队列中/未入库」三态有清晰视觉区分。

### 4.3 给开发工程师

- 凭据安全：`remix_userkey` AES-GCM 加密落库（密钥 `SL_ZLIB_SECRET`，未配置自动生成持久化）；密码仅在登录换取令牌瞬间存在于内存，不落库、不落日志；日志全面脱敏。
- 防风控：下载队列默认并发 1（可配 1~3），请求间加间隔，失败退避；不得并发轰炸 eapi。
- 适配层防御性解析：未知字段不报错；用固定样本响应做单元测试固定解析行为。
- 不绕过扫描器（同 4.1 第一条，工程师视角强调：入库代码的终点是「落盘 + 触发 scan」，不是写库）。
- 临时文件必须清理：任何失败路径（取消、校验失败、磁盘满、进程重启遗留）都不允许留下半截文件；重试前重新走前置校验。
- 错误按 §7 矩阵结构化（error_code/error_msg），前端依赖该契约渲染文案；i18n 词条 zh/en 成对提交。
- 保持 GPL-3.0：保留原版权声明，修改的文件头注明变更。

## 6. M1 验收口径（一句话）
